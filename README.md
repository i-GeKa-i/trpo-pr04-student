Репозиторий: https://github.com/i-GeKa-i/trpo-pr04-student

## Описание результата

Небольшое PHP-приложение без MVC «Заявки сотрудников»:

- выводит версию приложения и текущую дату (считает PHP на сервере);
- читает `dataset/employees.csv` и показывает таблицу сотрудников;
- фильтрует таблицу по отделу через GET-параметр `department` (без параметра — все записи);
- принимает заявку сотрудника через POST-форму (ФИО, email, отдел, стаж) с серверной валидацией: обязательность, длина, диапазон числа;
- при ошибках показывает сообщения возле полей и сохраняет введённые значения;
- принятые заявки пишет в `data/applications.json` и показывает в таблице;
- сценарии из `dataset/form_cases.json` проверяются скриптом `tests/check_cases.php`.

## Как используется dataset

- `employees.csv` читается в `loadEmployees()` через `fgetcsv`. Каждая строка превращается в массив функцией `parseEmployeeRow()`. По этим данным строятся таблица, список отделов в фильтре и в поле формы.
- `form_cases.json` читает `tests/check_cases.php` и прогоняет каждый сценарий через `validateInput()`.

## Сценарий проверки

1. Откройте главную: вверху видны версия приложения и сегодняшняя дата.
2. В таблице 5 сотрудников. Выберите отдел «Разработка» и нажмите «Показать» — останутся 2. Откройте `/` без параметра — снова все 5.
3. Отправьте форму с пустым ФИО, email `abc` и стажем `-2` — под полями появятся сообщения, введённые значения останутся.
4. В ФИО введите `<b>x</b>` — текст выводится как есть, тег не исполняется.
5. Заполните форму корректно — появится «Заявка принята», запись попадёт в «Принятые заявки».
6. Автопроверка (код выхода 0 — всё прошло):

```bash
php tests/check_cases.php
```

Результаты — в [docs/checks.md](docs/checks.md).

## GET и POST

- **GET** передаёт параметры в адресе (`?department=Поддержка`). Их видно, страницу можно сохранить в закладки. Подходит для фильтров и чтения, данные не меняет.
- **POST** передаёт данные в теле запроса, они не попадают в адрес. Подходит для отправки форм и изменения данных; здесь им создаётся заявка.

## Назначение htmlspecialchars

Функция заменяет `< > & " '` на HTML-сущности. Без неё введённая строка вроде `<script>…</script>` выполнилась бы в браузере (XSS). Всё, что пришло от пользователя или из файла, выводится через `e()` — обёртку над `htmlspecialchars($value, ENT_QUOTES, 'UTF-8')`.

## Путь данных от формы до HTML-ответа

1. Браузер отправляет POST на `/`.
2. `index.php` берёт значения `$_POST[...] ?? ''` и нормализует их через `trim`.
3. `validateInput()` возвращает массив ошибок `[поле => сообщение]`.
4. Есть ошибки — страница рисуется снова: значения в полях и сообщения возле них, всё через `e()`.
5. Ошибок нет — `saveApplication()` пишет заявку в `data/applications.json`, `loadApplications()` отдаёт её в таблицу, ответ — готовый HTML.
