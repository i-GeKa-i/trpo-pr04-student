# ПР №4 — PHP. Основы языка, запросы и обработка HTML-форм

Небольшое PHP-приложение без MVC: выводит таблицу сотрудников из `dataset/employees.csv`, фильтрует её по отделу (GET) и принимает заявку сотрудника через POST-форму с серверной валидацией. Сценарии проверки берутся из `dataset/form_cases.json`.

**Технологии:** PHP 8.1+ (встроенный сервер), HTML5, CSS. Без Composer и фреймворков.

## Требования к окружению

- PHP 8.1 или новее (`php -v`). Расширения сверх стандартных не нужны.
- Git.

## Запуск

```bash
git clone https://github.com/i-GeKa-i/trpo-pr04-student.git
cd trpo-pr04-student
php -S localhost:8000 -t public
```

Откройте <http://localhost:8000>. Если порт занят — возьмите другой (`localhost:8080`).

## Структура

```
public/index.php      точка входа: версия и дата, фильтр, форма, таблицы
public/style.css      оформление
src/functions.php     e(), loadEmployees(), parseEmployeeRow(), departmentsOf(),
                      filterByDepartment(), validateInput(), saveApplication(), loadApplications()
dataset/              employees.csv, form_cases.json (исходные данные работы)
data/                 сюда пишется applications.json (принятые заявки, в Git не попадает)
tests/check_cases.php проверка сценариев из form_cases.json
docs/checks.md        результаты проверок
```

## Что использует dataset

- `employees.csv` (разделитель `;`) читается через `fgetcsv` в `loadEmployees()`; каждая строка превращается в массив функцией `parseEmployeeRow()`. Из него же строится список отделов для фильтра и поля формы.
- `form_cases.json` читает `tests/check_cases.php` и прогоняет через `validateInput()`.

## Сценарий проверки

1. Главная показывает версию приложения и сегодняшнюю дату (выполняет PHP, а не браузер).
2. Таблица содержит 5 сотрудников. Выберите отдел «Разработка» → останутся 2. Без параметра `?department=` видны все.
3. Отправьте форму пустой, с email `abc` и стажем `-2` → список ошибок сверху, сообщения у полей, введённое сохранилось.
4. В поле ФИО введите `<b>x</b>` → текст выведен как есть, тег не исполняется.
5. Заполните форму корректно → «Заявка принята», запись появляется в таблице «Принятые заявки».
6. Автопроверка: `php tests/check_cases.php` (код выхода 0 = всё прошло).

## Ход выполнения (по шагам задания)

- Шаги 1–2: репозиторий, структура, dataset, запуск встроенным сервером.

## GET и POST

- **GET** передаёт параметры в URL (`?department=Поддержка`), их видно и можно добавить в закладки; подходит для фильтров и чтения. Не меняет данные.
- **POST** передаёт данные в теле запроса, не светит их в адресе; подходит для отправки формы и изменения данных (здесь — создание заявки).

## htmlspecialchars

Заменяет `< > & " '` на HTML-сущности. Без неё введённая строка `<script>…</script>` выполнилась бы в браузере (XSS). Поэтому всё, что пришло от пользователя или из файла, выводится через `e()` — обёртку над `htmlspecialchars($v, ENT_QUOTES, 'UTF-8')`.

## Путь данных от формы до HTML

Браузер → POST `/` → `$_POST[...] ?? ''` → `trim` → `validateInput()` вернула массив ошибок → при ошибках страница рисуется заново со старыми значениями (через `e()`) и списком ошибок; при успехе `saveApplication()` пишет в `data/applications.json`, а `loadApplications()` отдаёт записи в таблицу → HTML-ответ.
