# Employee Requests — учёт сотрудников и заявок

Небольшое веб-приложение на PHP для просмотра списка сотрудников и подачи заявок. Данные загружаются из CSV-файла, список можно фильтровать по отделу, а заявки проходят серверную проверку и сохраняются в файл.

Проект выполнен в рамках практической работы №4 по дисциплине «Технологии разработки программного обеспечения».

## Возможности

- Таблица сотрудников (ID, ФИО, отдел, стаж, email) из `dataset/employees.csv`.
- Фильтрация по отделу через GET-параметр `department`.
- Форма заявки сотрудника: ФИО, email, отдел, стаж.
- Серверная валидация: обязательность полей, длина ФИО, формат email, стаж — целое число от 0 до 50.
- Понятные сообщения об ошибках под полями; введённые значения сохраняются.
- Защита от XSS: весь пользовательский вывод экранируется.
- Список принятых заявок с хранением в `data/applications.json`.

## Установка и запуск

```bash
git clone https://github.com/i-GeKa-i/trpo-pr04-student.git
cd trpo-pr04-student
php -S 127.0.0.1:8000 -t public
```

Откройте в браузере: <http://127.0.0.1:8000>

Если порт 8000 занят, используйте другой, например `127.0.0.1:8080`.

## Использование

1. **Просмотр.** На главной странице отображаются версия приложения, текущая дата и таблица сотрудников.
2. **Фильтр.** Выберите отдел и нажмите «Показать». Без параметра `?department=` отображаются все сотрудники.
3. **Заявка.** Заполните форму и нажмите «Отправить заявку». При ошибках под полями появятся сообщения. При успехе заявка попадёт в таблицу «Принятые заявки».

## Проверка

```bash
php tests/check_cases.php
```

Скрипт прогоняет сценарии из `dataset/form_cases.json` и дополнительные проверки (пустое имя, неверный email, нечисловой и отрицательный стаж, фильтр). Код выхода `0` означает, что все проверки пройдены. Результаты — в [docs/checks.md](docs/checks.md).

## Как это работает

### GET и POST

- **GET** передаёт параметры в адресной строке (`?department=Поддержка`). Подходит для чтения и фильтрации: ссылку можно сохранить и отправить.
- **POST** передаёт данные в теле запроса, они не отображаются в URL. Подходит для отправки форм и создания записей — так подаётся заявка.

### Экранирование вывода

Функция `e()` — обёртка над `htmlspecialchars($value, ENT_QUOTES, 'UTF-8')`. Она заменяет `< > & " '` на HTML-сущности, поэтому введённая строка вида `<script>…</script>` отображается как текст и не выполняется (защита от XSS). Через неё выводятся все данные из формы и файлов.

### Путь данных от формы до страницы

1. Браузер отправляет POST-запрос на `/`.
2. `index.php` читает `$_POST[...] ?? ''` и нормализует значения через `trim`.
3. `validateInput()` возвращает массив ошибок.
4. При ошибках страница рисуется заново с введёнными значениями и сообщениями у полей.
5. При успехе `saveApplication()` записывает заявку в `data/applications.json`, `loadApplications()` отдаёт её в таблицу.
6. Ответ формируется как HTML с экранированием через `e()`.

## Изменения по шагам задания

- **Шаг 12.** Логика вынесена из разметки в `src/functions.php` (подключается через `require_once`): чтение данных, валидация и экранирование находятся в функциях, а `index.php` только вызывает их и выводит результат.
- **Шаг 13.** Добавлена фильтрация таблицы по GET-параметру `department`; без параметра выводятся все записи.
